Your files, sorted
on a loop.

A CLI that organizes your files from one YAML file. Categories say what goes where; movelooper moves, copies, links or archives it, once or as files arrive. Every run can be previewed first and undone after.

The shape of a run

You write the rules.
movelooper does the moving.

  1. Declare categories. A source, the extensions it takes, filters that leave files alone, and where the rest go.
  2. Preview with --dry-run. Every destination is resolved and printed, conflicts included, and nothing moves.
  3. Run it once, or watch. Watch mode waits until a file stops changing before it moves it.
  4. Take a batch back. movelooper undo restores everything one run moved.
movelooper.yaml
categories:
  - name: images
    source:
      path: ./Downloads
      extensions: [jpg, png]
    destination:
      path: ./Pictures
      organize-by: "{mod-year}/{mod-month}"
      conflict-strategy: hash_check  # drop exact duplicates
  - name: documents
    source:
      path: ./Downloads
      extensions: [pdf]
      filter:
        not:
          - match: { glob: "draft_*" }  # leave drafts alone
    destination:
      path: ./Documents
      rename: "{mod-date}_{name}.{ext}"
      conflict-strategy: rename
What it does

A file no rule matches is a file it never touches.

The config above, run on a Downloads folder. draft_notes.pdf stays because a filter left it; setup.exe stays because no category claims it.

The editor

An editor that knows the schema.

  1. Every field explained. The hint follows the cursor with the field's description, type, default and allowed values.
  2. Values picked, not guessed. Ctrl+O lists the values a field takes, such as an action or a conflict strategy.
  3. Nothing invalid reaches the disk. Saving validates the whole config, then shows the diff before it writes.

What is in the box

Rules for every file you collect.

One binary, no runtime. Linux, macOS and Windows are built and tested on every change.

▤ Category rules

Sources, extensions and destinations in plain YAML. extensions: [all] is a catch-all, and import: splits a config across files.

⌕ Filters that compose

Regex, glob, age, size and the real file type from its bytes, combined with not, any and all.

⇄ Four actions

move, copy, symlink or archive into a zip or tar.gz, chosen per category.

≠ Conflicts, decided

Rename, skip, overwrite, keep the newest, the larger, or drop the file when its hash says it is already there.

{} Tokens

Folders and names from the file itself: {mod-year}/{mod-month}, {mod-date}_{name-slug}.{ext}, hashes and sequences.

◎ Watch mode

Moves files as they arrive, once each has stopped changing, with retries for the ones still locked.

↺ Dry-run and undo

Preview any run before it happens, and revert any batch after, from a picker or by its id.

▣ An editor for the config

movelooper edit opens the YAML in a TUI with templates, undo, redo and validation on save.

⚑ Hooks and logs

Commands before and after a category runs. Logs print as a tree in your theme, or as JSON lines with --format json.

Commands

A handful of verbs.

movelooperMove files once across every category
movelooper --dry-runShow where everything would go, and move nothing
movelooper watchMove files as they arrive in the source folders
movelooper undoPick a past batch and put its files back
movelooper editEdit the config in a TUI, or start one from a template with -o
movelooper validateCheck a config and report every error
movelooper configPrint the path of the config that would load
movelooper self-updateInstall the latest release
